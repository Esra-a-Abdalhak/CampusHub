# مشروع إدارة المهام والمشاريع — Full Stack

المشروع الآن يتكون من:
- Front-End: HTML + CSS + JavaScript
- Back-End: Python + Flask
- Database: SQLite 3 عبر مكتبة `sqlite3`
- Algorithms: Python

## التشغيل على Windows

افتح Terminal داخل مجلد المشروع ثم:

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

ثم افتح:
`http://127.0.0.1:5000`

## التشغيل على Linux/macOS

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python3 app.py
```

ثم افتح:
`http://127.0.0.1:5000`

## قاعدة البيانات

عند أول تشغيل يتم إنشاء:

`task_manager.db`

والجداول:
- projects
- members
- tasks
- activity_log

لا تحتاج لإنشاء قاعدة البيانات يدويًا؛ `database.py` يقوم بإنشائها وتعبئتها ببيانات تجريبية.

## الخوارزميات

`algorithms.py` يحتوي على تطبيق يدوي لـ:
1. Merge Sort — بدون `sorted()` وبدون `list.sort()`.
2. Quick Sort — بدون `sorted()` وبدون `list.sort()`.
3. Divide & Conquer / Recursive لحساب إجمالي جهد المشروع.

واجهة "ترتيب المهام" تستدعي Python API وتعرض زمن التنفيذ بالميلي ثانية لكل خوارزمية.

واجهة "جهد المشروع" تستدعي الدالة العودية في Python وتعرض مجموع الساعات.

## الربط

JavaScript لا يخزن المهام في `localStorage` anymore.
كل العمليات الأساسية تمر عبر REST API:
- GET/POST للمشاريع
- GET/POST/PUT/DELETE للمهام
- POST للمهام الفرعية
- GET للتقرير
- GET لسجل التغييرات
- GET لمقارنة الخوارزميات
- GET لحساب جهد المشروع

## مطابقة متطلبات وصف المشروع

### المتطلبات الوظيفية
- إنشاء مشروع بالاسم والوصف وتاريخ البداية والنهاية.
- إنشاء المهام بالعنوان والوصف والأولوية وتاريخ التسليم.
- مهام فرعية بعلاقة أب/أبناء.
- توزيع كل مهمة أو مهمة فرعية على أحد أعضاء الفريق الخمسة المسجلين.
- لوحة Kanban بثلاثة أعمدة: جديد، قيد العمل، منتهي، مع تغيير الحالة وسجل زمني.
- تقرير نسبة الإنجاز الكلية وعدد المهام المنجزة لكل عضو.
- قاعدة بيانات SQLite3 حقيقية مرتبطة بالواجهة عبر Flask REST API.
- منع تواريخ تسليم المهام والمهام الفرعية قبل تاريخ اليوم من الواجهة والخادم.

### Sorting Comparison
- Merge Sort يدوي وQuick Sort يدوي بدون `list.sort()` أو `sorted()`.
- الترتيب حسب الأولوية أو التاريخ الأقرب.
- عرض قائمة المهام المرتبة وزمن التنفيذ بالميلي ثانية لكل خوارزمية.
- عرض تحليل Best/Worst Case، مع مقارنة زمن التجربة الحالية.

### Divide & Conquer
- حساب إجمالي ساعات المشروع اعتمادًا على شجرة المهام والمهام الفرعية.
- الحساب يتم باستدعاء ذاتي Recursive، وليس بجمع الفروع داخل حلقة `for`.
- التعقيد O(n) لأن كل عقدة تتم زيارتها مرة واحدة، مع الاعتماد على Call Stack.

### GitHub
وصف المشروع يطلب مستودع GitHub، وفروع `main` و`dev` وفروع Features، وPull Requests مع Code Review ورسائل Commit واضحة. هذه خطوات تسليم وإدارة إصدارات ينفذها الفريق على GitHub، وليست وظيفة داخل التطبيق نفسه.
